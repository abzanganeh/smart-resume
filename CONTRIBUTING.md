# Contributing

Thanks for your interest in contributing to Flint Apply.

## Before You Start

- Read `README.md` and `LICENSE`.
- Open an issue describing your proposed change for non-trivial work.
- Keep changes focused: one logical change per pull request.

## Development Workflow

1. Fork or branch from `main`.
2. Create a feature branch:
   - `feature/<short-description>`
   - `fix/<short-description>`
   - `chore/<short-description>`
3. Implement changes with tests and docs updates where needed.
4. Run local quality checks before opening a PR.
5. Open a PR with:
   - problem statement
   - implementation summary
   - testing evidence
   - risk/rollback notes for infra/data changes

## Commit Message Style

- Use imperative mood (for example: `Add stripe webhook idempotency`)
- Keep commits small and reviewable
- Avoid mixing unrelated changes in one commit

## Pull Request Requirements

- CI must pass
- Code review approval is required
- Security-sensitive changes may require an additional maintainer review

## Contributor License Agreement (CLA)

By submitting a contribution, you agree that:

- you own the code you submit, or have rights to submit it
- your contribution may be redistributed under this repository's license
- you grant the project maintainers the right to use your contribution in
  both open and commercial license distributions of this project

Maintainers may request explicit CLA confirmation for substantial
contributions.
