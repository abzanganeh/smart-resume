PHASE 4 — QA SELF-CHECK + ATS GUIDANCE

Your task: evaluate the tailored resume against the 8-point QA checklist AND produce ATS score guidance. Be strict and objective.

Checklist items to evaluate:
1. "Tailored to one specific JD" — are all sections clearly targeting this specific role?
2. "Top JD keywords in Skills, Experience, Summary" — does each of the top 5-8 must-have keywords appear in at least two of: Skills, an Experience bullet, and the Summary?
3. "Bullets start with action verbs + metrics" — does every single bullet start with an action verb AND include a quantified metric?
4. "Recruiter-friendly language" — is there any internal jargon, acronym not in the JD, or obscure title?
5. "Only relevant experience included" — are there any bullets or sections with no connection to this JD?
6. "Within page limits" — is it within 1 page (early/mid) or 2 pages (senior)?
7. "Professional contact details" — is the email address professional (full name, no nicknames)?
8. "ML transition signals visible" — if is_transitioning_to_ml = true, are projects/certifications/stats visible?

Rules:
- status "pass": the item fully passes with no issues.
- status "warn": the item mostly passes but has a minor gap worth noting.
- status "fail": the item clearly fails and requires user action.
- Any unresolved entry in metrics_needed automatically makes item 3 "fail".
- user_action_required: list only items the USER must fix (e.g. supply a missing metric). Do not include items the AI already resolved.
- overall_status: "fail" if any item is fail; "warn" if any item is warn; "pass" only if all pass.

ATS GUIDANCE (required fields — emit all four directly in JSON, no post-processing):

ats_score (0–100):
- Integer ATS compatibility score for the current tailored resume against this JD.
- This is NOT the Phase 2 audit score; it reflects post-rewrite ATS readiness only.

score_ceiling (0–100):
- Maximum ATS score achievable with the current JD + master resume content (before further user edits).
- Must be >= ats_score. Reflect realistic limits (e.g. missing experience cannot be fabricated).

blocking_issues (array):
- Every concrete issue preventing a higher ATS score.
- Each item: category, description, suggestion (actionable rewrite text or exact keyword to add), impact (high/medium/low), fix_effort (one_click | user_input | manual_rewrite).
- Order: impact descending (high → medium → low), then fix_effort ascending (one_click → user_input → manual_rewrite).

quick_wins (array):
- Subset of blocking_issues where impact = "high" AND fix_effort = "one_click".
- Same object shape as blocking_issues entries. Order by highest impact first.

Category guide:
- keyword: missing or weak JD keyword placement
- bullet: weak action verb, vague phrasing, or structure issue
- metric: missing quantified result
- format: ATS-unfriendly formatting (columns, icons, etc.)
- length: too long/short for career stage
- section: missing, irrelevant, or misordered section

Output ONLY valid JSON. No prose before or after.
