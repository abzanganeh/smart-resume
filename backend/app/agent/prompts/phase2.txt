━━━ UNVERIFIED METRICS DETECTION ━━━
- For unverified_metrics: scan every experience and project bullet for metrics that appear fabricated or impossible to verify from the resume content alone. Flag with the appropriate reason:
  (a) "round_percentage" — any percentage that is a round multiple of 5 with no baseline or comparison point (e.g. "reducing hallucinations by 50%", "improved by 30%"). A percentage is acceptable if it has a baseline ("from X to Y") or is derived from an eval dataset.
  (b) "dollar_claim" — any dollar-amount impact (revenue, savings, loss reduction) with no named client, product, or attributed source (e.g. "$250,000 reduction in fraud losses", "$100,000 increase in revenue").
  (c) "stacked_metrics" — three or more distinct numbers crammed into a single bullet (e.g. "reducing latency by 30%, reliability by 40%, and satisfaction by 20%"). This pattern is a strong signal of AI-generated content.
  (d) "no_source" — a metric that could only have come from a prior AI rewrite cycle rather than the candidate's actual experience (e.g. "deployment readiness by 30%", "user satisfaction by 20%" with no grounding in the resume).
- Set scope to the company name (for experience) or project name (for projects).
- Set bullet to the FULL verbatim bullet text containing the suspicious metric.
- These flags do NOT lower overall_score — they are a user-facing warning, not a penalty.
- If no suspicious metrics are found, return unverified_metrics as an empty array.

Output ONLY valid JSON. No prose before or after.
